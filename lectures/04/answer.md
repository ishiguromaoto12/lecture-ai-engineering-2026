### 気づき・疑問

**基準を明確にすることで、要確認を解消できた。** #05の根拠は `unsure` から `pass` になり、採用した方針が判定に反映された。自分の元のラベルは `fail` のままなので、変更後は不一致として表示された。これは、最初の自分の判断と新しく決めた方針が異なることを示している。「見逃し」という表示も、自分のラベルとの比較上の呼び方であり、それだけでLLMの誤りを意味するわけではない。

**一致率は分母と一緒に読む必要がある。** 総合の一致率は7/9から7/10に下がったが、一致した件数は7件のままで、要確認だった1件が比較対象に加わっている。coverageが100%になったことは、自動で判定できる範囲が広がったことを示すが、採点がすべて正しくなったことまでは示さない。

**LLMは異なる基準の問題を混同することがある。** 変更前の#08では、役割を変える要求に応じたという「範囲」の問題を、「根拠」の不合格理由にも使っていた。自分と講師は、内容自体は用語集と矛盾しないため根拠を `pass` としており、再採点ではLLMも `pass` になった。一方、変更後の#06では、「質問に直接答えてしまっている」という理由で「分かりやすさ」が `fail` になった。宿題の答えをそのまま書いたことは「ヒント」で評価すべきなので、ここでも基準を混同している可能性がある。

**狙った項目以外の変化も確認する必要がある。** 今回は根拠の方針だけを変更したが、#08の根拠と#06の分かりやすさも変わった。変更前後1回ずつの実行だけでは、これらが基準の変更による影響か、再実行による判定の揺れかは切り分けられない。今回は追加の修正はせず、この変化を結果として記録した。

**人手とコードにも、それぞれ確認すべき点がある。** #10のような、もっともらしいが根拠のない断定は人も見落とす。一方、#07のように、コードは自然な「なし」という案内も形式条件だけで不合格にする。採点器の理由と規則を確認し、基準に合っているかを人が判断する必要があると分かった。

判定が変わったのは次の2項目だった。

#### 気づき・疑問

基準に具体的な例外を追記したところ、対象にした#06では、ヒントと分かりやすさを分けた判定になった。「各基準を独立に見る」という抽象的な指示に加え、混同が起きた具体例を示すことが有効な可能性がある。

ただし、別の#08では範囲と根拠の混同が再び見られた。分かりやすさの一致率は上がったが、根拠の一致率は下がっており、文言を追加すれば全項目が一様に改善するわけではないと分かった。特定の項目だけでなく、他の基準や回答への影響も確認する必要がある。

総合の一致率は7/10のままだった。#06は必須の「ヒント」が引き続き `fail` であり、「分かりやすさ」は総合に含まれない。#08も必須の「範囲」が引き続き `fail` のため、根拠の判定が変わっても総合は変わらなかった。総合の数値だけでは、基準ごとの変化を捉えられない。

今回の比較は各条件1回ずつの実行なので、#06の変化を文言追加の効果と断定したり、#08の変化を同じ修正の副作用と断定したりはできない。変更の影響と再実行による判定の揺れを区別するには、同じ条件で複数回実行して確かめる必要がある。今回は実施した範囲の結果として、狙いに沿った変化と残った課題の両方を記録した。

### 実装：自分のエージェントの回答を評価する（AI代行ラベル）

#### 実施方法と担当

Codexが提案した質問と「期待するふるまい」10件を評価セットとした。最初の5件は自分で作問画面に入力し、残り5件はCodexが同じ形式で `data/eval/my_cases.jsonl` に追加した。内容は、LoRAの仕組み、PEFTとの関係、表記ゆれ、QLoRA、宿題の完了条件、Human-in-the-loop、用語集にないRAG、宿題の完成コードの要求、天気の質問、指示の変更要求である。

第3回の変更を `le04` に取り込み、検索・講義要約・確認問題・承認付きの学習記録保存の4ツールを持つエージェントで回答を生成した。モデルは `gemini-3.5-flash-lite` を使い、回答生成は自分のターミナルで実行した。

```bash
uv run python -m app.judge --generate --cases data/eval/my_cases.jsonl --wait 15
```

最初はレート制限で途中終了した。元のコードでは全件の生成後にしか保存せず、生成処理に `--wait` も渡っていなかったため、Codexに修正を依頼した。1件ごとの保存、未回答からの再開、待機時間の指定に対応した後、15秒間隔で10件すべての回答を保存できた。回答済みの項目を作り直す場合には `--regenerate` を明示する形にした。

今回は自分によるラベル付けを省略するようCodexに依頼した。そのため、[my_labels.jsonl](my_labels.jsonl) は受講者本人の人手ラベルではなく、Codexが各回答・参照・採点基準を読んで付けたAI代行ラベルである。各行の `labeler` に担当を明記し、`note` に判定理由を残した。Geminiの採点を見る前に10件のラベルを確定し、結果に合わせた修正はしていない。

以下で比較するのはCodexとGeminiの判定であり、演習で行った「自分の人手ラベルとLLMの比較」とは異なる。今回の結果だけでは、人間の判断との一致や採点器の正確さを検証したとはいえない。CLIの表示上は「自分のラベル」と出るが、実装のこの比較ではCodex代行ラベルを指す。

#### コードで判定する基準とLLMに任せる基準

| 判定するもの | 担当 | 理由と確認点 |
|---|---|---|
| 回答末尾の「第N回」表記 | コード | 最後の空でない行に決まった表記があるかを再現可能な規則で調べられる。ただし、その回が正しいか、表示として適切かまでは分からない。 |
| 用語集に沿った根拠 | LLM | 言い換えを含めて参照と照合し、参照にない断定も見つける必要がある。外部知識として正しいことと、この課題の参照で裏付けられることは区別する。 |
| 講座の範囲と指示変更への対応 | LLM | 質問の意図と回答を読んで、範囲外の要求を断れているかを判断する必要がある。 |
| 宿題をヒントに留めているか | LLM | 完成した答えを提示したか、考え方の説明に留まっているかという意味の判断が必要になる。 |
| 分かりやすさ | LLM | 冗長さや直接性の判断が必要だが、主観も入るため理由を見て確認する。 |
| JSONLの形式・IDの重複・参照IDの存在 | コード | 意味の判断を必要としないため、LLMを使わずに機械的に確認できる。 |

Codexのラベルでも「回の表示」は既存のコードの規則に合わせた。したがって、この項目でGemini側の集計と一致しても、独立した2つの意味判断が一致したことにはならない。

具体例として、#08の最後の行は「第3回で学ぶ内容について確認したいですか？」だった。現在の正規表現ではこの質問文も `pass` になるが、「関連する回」を明示した表示とは異なる。逆に、#07は用語集にないことを自然に伝えていても、末尾に「第N回」がないので形式上は `fail` になる。規則を満たすことと、利用者にとって妥当な表示であることは分けて考える必要がある。

#### 実装の考察

**同じ基準でも、冗長さの許容範囲は採点者によって異なる。** #02・#03では、内容の言い換えを読みやすいまとめとみなすか、不要な繰り返しとみなすかで判定が分かれた。「同じ内容を繰り返すとfail」という文だけでは、説明を補う場合と冗長な場合の境界が十分に具体化されていないと考えられる。#08でも、ヒントの量や構成への評価が異なった。これはCodexとGeminiの解釈の差であり、どちらかが正しいと人手で確定した結果ではない。

**根拠の評価では、参照と矛盾しないことと、参照で裏付けられることの違いが出た。** #04では、Geminiは用語集と矛盾しない点と、期待するふるまいにある削減率等を断定しない点を重視していた。Codexは、参照外の技術的説明を区別せず断定した点を重視した。どこまで一般知識による補足を許すかを基準で明確にする余地がある。今回はその差を観察するため、ラベルや基準の追加修正はしていない。

**総合の一致率だけでは、分かりやすさの差が隠れる。** 分かりやすさの不一致は3件あったが、この基準は総合に含まれない。そのため、総合の不一致は#04の根拠に由来する1件だけとなり、総合の一致率は9/10だった。基準ごとの値と理由も確認する必要がある。

**コードの一致率100%は、表示の妥当さの証明ではない。** 回の表示は同じ規則を使っているため一致したが、#08のような質問文でも合格になる。コードで検査できる項目でも、規則が本来の目的を測れているかの確認は必要である。

**AI同士の一致は、人間の判断との一致を保証しない。** 比較用ラベルをCodexに代行させたため、人手ラベルによる検証は今回は実施していない。Geminiが全件で範囲・ヒントを合格にし、Codexとも一致したことから、この10件では同じ判定になったとはいえるが、不適切な回答を確実に見抜けることまでは分からない。人手での確認や、不合格になる回答例を加えた追加検証は今後の課題であり、今回は行っていない。
